# PRD — RO Proposal Studio (working title)

Version 0.1 · Status: Draft for review · Owner: PAKSAFE

---

## 1. Overview

### 1.1 Problem
Technical & commercial proposals for RO / water-treatment plants are written by hand in MS Word. This is slow and tied to one laptop. Every proposal repeats the same "material manual" (specs of filters, pumps, membranes, instrumentation), the layout must be re-aligned each time, and sizing questions (multimedia vessel size, FRP vs MS, number of cartridge filters at 5 µm / 1 µm) are sent to the technical team for answers.

### 1.2 Solution
An installable, offline-capable web app that:
1. keeps a library of components and plant templates (write specs once),
2. calculates the sizing numbers the sales engineer currently asks others for,
3. generates a branded, correctly aligned PDF proposal (Technical + Commercial),
4. tracks clients, proposals and their status,
5. works with no internet and syncs when online.

### 1.3 Goals
- G1: Produce a complete proposal in **under 10 minutes** (today: much longer).
- G2: **Zero manual layout work** — alignment, numbering, TOC and page numbers are automatic.
- G3: Sizing answers (multimedia filter, cartridge filters, RO flows) available **without asking the technical team**.
- G4: Fully usable **offline** on Windows and Linux; data syncs when online.
- G5: Support **multiple company brands** from one app.

### 1.4 Non-goals (v1)
- Mac packaging (PWA may work on Mac, but not a target).
- Full RO membrane projection software (e.g. vendor design programs). The app does basic flow arithmetic only.
- E-signature, client portal, accounting/invoicing, inventory.
- AI-generated content (optional later, needs internet).

### 4.5 Calculators
All calculators use the shared design flow. Results can be applied to the proposal with one button and remain editable.

**FR-CAL-1 Multimedia filter**
- Inputs: design flow Q (m³/hr), service hours, backwash hours, design velocity, media layers (name, bed depth, bulk density), margin %, preferred vessel type (auto / FRP / MS).
- Outputs: IFR, required area, calculated diameter, **standard vessel size** (next size up from the editable list), **actual velocity**, shell height check, media weight per layer and total, media cost (internal), **recommended vessel type (FRP / MS)** with the reason, number of vessels if the flow exceeds the single-vessel limit, **rated flow** of the chosen vessel.

**FR-CAL-2 Cartridge filters**
- Inputs: RO feed flow, safety margin, stages (1 stage = 5 µm, 2 stages = 5 µm → 1 µm), preferred length (10/20/30/40 in), slim or jumbo.
- Outputs per stage: cartridges needed = ceil(flow × margin ÷ ideal flow per cartridge), smallest suitable housing, housing quantity, and the matching "No. of filters per housing" and cartridge quantity (these must agree).
- Each stage sees the full flow; stages are in series, not split.

**FR-CAL-3 RO flows**
- Product = feed × recovery; reject = feed − product; GPD ↔ m³/hr ↔ GPM conversions; suggested membrane count from membrane rated permeate vs required product (editable).

**FR-CAL-4** All constants/limits come from settings tables (FR-SET-3), not code. **M**

## 6. Key user flows

1. **New proposal**: Proposals → New → choose company, client/site, template → enter design parameters → run calculators and apply → adjust specs → set pricing/terms → preview → export PDF → mark Sent.
2. **Size a filter only**: Calculators → Multimedia filter → enter flow → get size, FRP/MS, media weights → optionally apply to a proposal.
3. **Revise**: open Sent proposal → Create revision → edit → export Rev-02.
4. **Work offline**: open installed app → create/edit proposals → sync indicator shows "pending" → reconnect → auto-sync.
5. **Follow up**: Dashboard → Due today → open client → log call → set next follow-up.

## 7. Business rules

**R-1 Flow chain.** Feed (GPD) → m³/hr = GPD × 3.78541 ÷ 1000 ÷ 24. Product = feed × recovery. Reject = feed − product.

**R-2 Multimedia filter** (reverse-engineered from the current Excel sheet)
- IFR = Q × 24 ÷ service hours
- Area = IFR ÷ velocity
- Diameter = √(4 × Area ÷ π)
- Choose next standard size ≥ calculated diameter; recompute velocity from the chosen size
- Media weight = Area × bed depth × bulk density
- Media cost = weight × rate per kg
- Freeboard check: shell height ≥ total bed depth × (1 + freeboard %)

**R-3 FRP vs MS.** Rule engine with thresholds set in settings (max FRP diameter, max pressure, max temperature, water type). Default result shown with its reason. *Thresholds to be confirmed by the technical team.*

**R-4 Cartridge filters.** Quantity = ceil(feed flow × margin ÷ ideal flow). Ideal flows from the table: 10" slim 1; 20" slim 2; 20" jumbo 3–4; 30" slim 3; 40" slim 4 m³/hr. Housing = smallest slot count ≥ quantity.

**R-5 Reference numbers.** Unique per company; gaps allowed; revisions keep base number.

**R-6 Proposal snapshot.** Specs and client details are copied into the proposal; later library or client changes do not alter existing proposals.

## 8. Reference data from current documents (seed / test data)

- **Sample proposal** PS/PRO/26/0646, 10,000 GPD BWRO: feed 10,000 GPD (1.58 m³/hr), recovery 50%, product 5,000 GPD, design TDS 5,000 ppm, price PKR 735,000, payment 75/15/10, delivery 2–4 weeks.
- **Excel test case**: Q = 6 m³/hr, service 23.5 h, backwash 0.5 h, velocity 16 m/hr → IFR 6.13, area 0.383 m², diameter ≈ 698 mm; gravel 200 mm @2500, sand 500 mm @1650, anthracite 75 mm @850, activated carbon 100 mm @529.

### Issues found in current documents (fix in seed data)
1. Excel "276" total is the sum of the rate column; total media weight should be the sum of weights.
2. Activated carbon has weight but zero cost.
3. Gravel density 2500 kg/m³ looks like particle, not bulk density — verify with supplier.
4. "30 inch" shown next to 700 mm does not match (700 mm ≈ 27.6").
5. Proposal: multimedia flow "03~05 m³/hr" is too high for a 16" vessel (≈2.1 m³/hr at 16 m/hr); cartridge quantity "01" conflicts with "05 filters/housing"; typos "PENAL", "OVERLAOD", "PVS", stray "M" under Feed Pump; HP pump voltage 200 V vs feed pump 380–415 V to be checked.

## 9. Success metrics
- Time to produce a proposal ≤ 10 minutes (target) vs current baseline (measure).
- Zero layout corrections needed after export in 9 of 10 proposals.
- 100% of sizing questions answered in-app.
- No lost or duplicate reference numbers.

## 10. Acceptance criteria for MVP
1. Recreate proposal PS/PRO/26/0646 from the BWRO template in the app; PDF matches the original structure (cover, TOC, 15 technical sections, commercial page).
2. Calculator reproduces the Excel test case within rounding.
3. Cartridge calculator returns 1 × 20" element for 1.58 m³/hr feed (1 stage) and warns when housing slots ≠ quantity.
4. PDF generated with network disabled.
5. Changing a library component does not alter an existing proposal.

## 12. Risks
| Risk | Mitigation |
|---|---|
| PDF layout differs from current Word design | Build PDF template first, compare side by side |
| Sync conflicts / data loss | Local-first, tombstones, JSON export, sync log |
| Free DB pauses | Keep-alive job, local copy, monthly export |
| Wrong sizing rules cause wrong proposals | Rules in editable tables, test against Excel, technical team sign-off |
| AI-generated code quality (AI Studio) | Pure tested calc engine, code in GitHub, review in editor |
