# TRD — RO Proposal Studio (working title)

Version 0.1 · Companion to `PRD.md`, `DESIGN.md`, `TECHNICAL_FLOWCHART.md`

---

## 1. Architecture summary

**Offline-first PWA.** The UI reads and writes only to a **local database (IndexedDB via Dexie)**. A sync engine copies changes to and from **Supabase (Postgres + Auth + Storage)** when online. PDFs are generated **in the browser**, so they work offline. The app is deployed as static files on **Vercel**. No custom backend server is needed; server-side logic lives in a few Postgres functions.

```
 Browser / installed PWA
 ├─ React UI
 ├─ Domain layer (calc engine, pricing, ref numbering)   ← pure TypeScript
 ├─ Local DB (Dexie / IndexedDB)  ← source of truth for the UI
 ├─ Sync engine (outbox + pull cursors)
 ├─ PDF engine (@react-pdf/renderer)
 └─ Service worker (Workbox) — caches the app shell
          │  (only when online)
          ▼
 Supabase: Postgres + RLS + Auth + Storage      Vercel: static hosting
```

Design principles
1. Local-first: no screen waits for the network.
2. Pure domain logic: calculations never touch UI or storage, so they are testable against the Excel sheets.
3. Rules as data: limits, sizes, densities, thresholds live in settings tables.
4. Snapshot on write: proposals copy specs and client details.
5. Money as integers (minor units).

## 4. Data model

### 4.1 Conventions (all synced tables)
| Column | Type | Purpose |
|---|---|---|
| `id` | uuid (client generated) | primary key |
| `org_id` | uuid | tenant; used by RLS |
| `created_at` | timestamptz | |

### 4.2 Tables
**Core**: `organizations`, `org_members(org_id, user_id, role)`, `devices`, `companies`, `settings_kv`.

**Clients**: `clients`, `contacts`, `sites`, `water_analyses`, `activities`, `client_files`.

**Library**: `component_categories`, `components(category_id, name, specs jsonb, cost_minor, archived)`, `templates`, `template_items(template_id, component_id, qty, sort)`.

**Rules**: `media_catalog(name, bulk_density, rate_minor_per_kg)`, `vessel_sizes(diameter_in, diameter_mm, height_options jsonb, type)`, `cartridge_types(length_in, micron, form slim|jumbo, ideal_flow_m3h)`, `housing_types(form, length_in, slots)`, `rule_settings` (key/value: velocity limits, freeboard %, FRP/MS thresholds, margins).

**Proposals**: `proposals`, `proposal_items(proposal_id, source_component_id, name, qty, sort, specs jsonb, unit_price_minor)`, `proposal_calcs(proposal_id, kind, inputs jsonb, outputs jsonb)`, `proposal_taxes`, `proposal_snapshots(proposal_id, rev, data jsonb, pdf_path, created_at)`.

**Numbering**: `ref_counters(company_id, year, next_value)`, `ref_blocks(company_id, year, device_id, start_value, end_value, next_unused)`.

### 4.3 Key DDL (sketch)

```sql
create table proposals (
  id uuid primary key,
  org_id uuid not null,
  company_id uuid not null references companies(id),
  client_id uuid references clients(id),
  contact_id uuid references contacts(id),

  title text,
  design jsonb not null,                    -- feed_gpd, recovery, tds, pressure, temp...
  currency text not null default 'PKR',
  fx_rate numeric,
  price_mode text not null default 'lump' check (price_mode in ('lump','grouped','itemized')),
  lump_amount_minor bigint,
  tax_lines jsonb not null default '[]',
  payment_terms jsonb not null default '[]', -- [{label, percent}]
  delivery_text text,
  validity_days int,

  won_po_no text, won_value_minor bigint, lost_reason text,
```

## 5. Sync design

### 5.1 Rules
- UI always writes to Dexie first, sets `client_updated_at = now`, marks `_dirty`, and adds an **outbox** entry.
- **Push**: when online, send dirty rows per table in batches (upsert). The server accepts a row only if incoming `client_updated_at` is newer than the stored one (last write wins).
- **Pull**: for each table, request rows with `server_updated_at > last_cursor`, apply to Dexie (skip if local dirty row is newer), store the new cursor.
- **Deletes**: set `deleted_at`; tombstones sync like normal rows and are purged after 90 days.
- **Order**: push, then pull; parents before children (companies → clients → proposals → items).
- **Triggers**: app start, back online event, after local save (debounced 5 s), manual "Sync now", every 5 min when visible.
- **Errors**: exponential backoff with jitter; visible status (Synced / Pending n / Offline / Error); log last 50 events in Settings.
- **Clock skew**: pull cursors use **server** time only; client time is used only to compare edits to the same row.

### 5.2 Upsert with "latest wins" (SQL sketch)

```sql
create or replace function upsert_row_guard() returns trigger as $$
begin
  if tg_op = 'UPDATE' and new.client_updated_at <= old.client_updated_at then
    return null;               -- ignore stale write
  end if;
  new.server_updated_at := now();
  return new;
end $$ language plpgsql;
-- attach as BEFORE INSERT OR UPDATE trigger on every synced table
```

### 5.3 Reference-number block reservation

```sql
create or replace function reserve_ref_block(p_company uuid, p_year int, p_device uuid, p_size int default 10)
returns table(start_value int, end_value int)
language plpgsql security definer as $$
declare s int;
begin
  insert into ref_counters(company_id, year, next_value) values (p_company, p_year, 1)
  on conflict (company_id, year) do nothing;

  update ref_counters set next_value = next_value + p_size
   where company_id = p_company and year = p_year
  returning next_value - p_size into s;

  insert into ref_blocks(company_id, year, device_id, start_value, end_value, next_unused)
  values (p_company, p_year, p_device, s, s + p_size - 1, s);

  return query select s, s + p_size - 1;
end $$;
```

Client behaviour: keep ≥ 3 unused numbers per company; when online and below that, call `reserve_ref_block`. First-ever use offline: allow a **provisional** number (`TEMP-xxxx`) that is replaced on first sync, and block *Sent* status until a final number exists. The unique constraint `(org_id, company_id, ref_base, rev)` is the final safety; a clash on sync auto-renumbers the later proposal and flags it.

### 5.4 Row Level Security (pattern)

```sql
alter table proposals enable row level security;
create policy org_isolation on proposals
  using (org_id in (select org_id from org_members where user_id = auth.uid()))
  with check (org_id in (select org_id from org_members where user_id = auth.uid()));
```
Repeat for every table. Storage buckets use the same org-based policy on the path prefix `org_id/...`.

## 6. Calculation engine (`/src/domain`)

Pure functions, no I/O. All inputs/outputs typed with Zod. Rounding only at display.

### 6.1 Constants and conversions
- 1 US gallon = 3.78541 L → `gpdToM3h(g) = g * 3.78541 / 1000 / 24`
- `m3hToGpm(x) = x * 4.40287`, `gpmToM3h(x) = x / 4.40287`
- inch ↔ mm = 25.4

### 6.2 Multimedia filter

```ts
type MmfInput = {
  qM3h: number; serviceH: number; backwashH: number; velocityMh: number;
  marginPct?: number;
  layers: { name: string; depthMm: number; bulkDensity: number; ratePerKg?: number }[];
  vesselType: 'auto' | 'frp' | 'ms';
};
type MmfOutput = {
  ifrM3h: number; areaM2: number; calcDiameterMm: number;
  chosen: { type: 'frp'|'ms'; diameterIn: number; diameterMm: number; heightMm: number; count: number };
  actualVelocityMh: number; ratedFlowM3h: number;
  layers: { name: string; weightKg: number; costMinor?: number }[];
  totalWeightKg: number; freeboardOk: boolean; warnings: string[]; reason: string;
};
```
Steps: `ifr = q*(1+margin)*24/serviceH` → `area = ifr/velocity` → `d = sqrt(4*area/π)` → pick the smallest standard size ≥ `d` (try 1 vessel; if larger than the largest allowed FRP size, try 2, 3, … vessels each handling `ifr/n`) → recompute `actualVelocity = ifr/(n*π*D²/4)` → weight per layer = `π*D²/4 * depth * density` using the **chosen** diameter → freeboard check → type rule (§6.4).

### 6.3 Cartridge filters

```ts
type CartInput = { feedM3h: number; marginPct: number; stages: 1 | 2; lengthIn: 10|20|30|40; form: 'slim'|'jumbo' };
// per stage: micron 5 (stage 1), micron 1 (stage 2)
count = ceil(feedM3h * (1+marginPct/100) / idealFlow(type))
housing = smallest housing_types where slots >= count and form/length match
```
Output also returns `elementsPerHousing`, `housingQty`, `totalElements`, and a validation message if slots ≠ count.

### 6.4 FRP vs MS rule

```
if diameterMm <= rule.maxFrpDiameterMm
   && pressureBar <= rule.maxFrpPressureBar
   && tempC <= rule.maxFrpTempC
   → FRP  (reason lists the passed checks)
else → MS (rubber-lined / epoxy-coated per setting) with the failed check as reason
```
Thresholds come from `rule_settings`. Defaults are placeholders until the technical team signs off.

### 6.5 RO flows
`product = feed * recovery; reject = feed - product; membranes = ceil(productGpd / ratedPermeateGpd / designFactor)` (design factor editable, default 1.0).

### 6.6 Pricing
Totals in integer minor units; tax per line rounded half-up; `paymentTerms` amounts = `round(total * percent/100)` with the last term absorbing the rounding difference.

### 6.7 Required unit tests
- Excel case: Q=6, service 23.5, BW 0.5, v=16 → IFR 6.128, area 0.383, d≈698 mm.
- 10,000 GPD feed → 1.577 m³/hr; 16" vessel → velocity ≈ 12.4 m/hr, rated flow ≈ 2.07 m³/hr at 16 m/hr.
- Cartridge: 1.58 m³/hr, margin 20%, 20" slim (2 m³/hr) → 1 element.
- Payment split 75/15/10 of PKR 735,000 sums exactly to the total.

## 7. PDF generation

- Engine: `@react-pdf/renderer`, A4, fonts registered from `/public/fonts` (offline).
- **Theme object** from the selected company (colors, logo as data URL, watermark, header/footer text).
- Fixed elements per page: header (logo + wordmark + rule), footer (rule + page number box), watermark (absolute, centered, low opacity). Cover page has no header/footer.
- Spec blocks: two-column rows (label | value). Section title uses `minPresenceAhead` / `wrap={false}` so headings never sit alone at page bottom.
- **Table of contents with page numbers: two-pass render.** Pass 1 renders the document and records each section's page number through the `render` callback; pass 2 renders again with the TOC filled. Results cached by a hash of the proposal data.
- Sections numbered automatically from item order; commercial page built from price mode.
- Output as `Blob` → preview in an `<iframe>`/PDF viewer, download, or save snapshot.
- Performance: render in a **Web Worker** if main-thread blocking is noticeable.
- Determinism: the same data produces the same PDF; the snapshot stores data JSON plus the PDF blob.

## 8. PWA and offline

- Manifest: name, icons (192/512, maskable), `display: standalone`, theme colors.
- Service worker: **precache** the app shell, fonts, icons; runtime cache for nothing sensitive; update flow shows "New version available — Reload".
- Call `navigator.storage.persist()` on first run to reduce the risk of browser eviction; show storage usage in Settings.
- Install: Chrome/Edge "Install app" on Windows and Linux.
- Auth offline: Supabase session persists locally; if the token cannot refresh offline the app keeps working on local data and queues sync until sign-in succeeds.
- Files (Storage): upload when online; cached on demand; "keep offline" stores the blob in IndexedDB.
- Logos stored as data URLs (≤ ~200 KB) inside company records.

## 9. Security and privacy

- Only the Supabase **anon (publishable) key** is in the client; never the service key.
- RLS on every table and storage bucket (§5.4).
- Zod validation on all form input, imports, and pulled rows.
- No secrets in the repository; Vercel/GitHub environment variables.
- Optional app lock screen (PIN) after idle; recommend disk encryption; sign out on shared devices.
- Content Security Policy header via Vercel config; no third-party scripts at runtime.
- Backups: user-triggered JSON export includes all tables (excluding auth data).

## 11. Testing strategy

- **Unit** (Vitest): every domain function, plus the Excel reference cases.
- **Data** : Dexie repository tests; sync tests with a fake server (conflict, tombstone, out-of-order, retry).
- **PDF**: snapshot test of text content and page count for the sample proposal; visual comparison by hand during MVP.
- **E2E** (Playwright): create proposal offline (network disabled), reconnect and verify sync, export PDF.
- **Manual**: Windows + Linux install and offline run, update flow.
